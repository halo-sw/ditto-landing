확인일: 2026-11-12 (KST). 지정된 6개 주소 모두 공개 HTML 요청에서 HTTP 200을 받았다. Skeep 5개 주소는 웹 검색 도구에서 열리지 않았지만, 직접 HTML/CSS/JS 읽기와 Chrome 1440×960 화면 검증으로 확인했다. 현재 사이트에는 일반 HTML 페이지와 Next/React 페이지가 섞여 있다. 이전 기록의 “전부 라이브러리 없이 구현”은 현재 상태와 다르다.

## 2. 최종안에 옮길 설계

### 한 페이지의 흐름

소개 → 가까워지기 어려운 이유 → 세 핵심 개념 → 플래터 체험과 위젯 유형 → 디토 전달 과정 → ASCII 주파수 → 피드·그룹 채팅·카메라 → 6개월 관계 지도 → 아날로그 미니앱 → 사진 촬영과 초대장 → FAQ·설치.

사용자가 준 문안의 순서를 유지한다. 예전 하위 페이지로 이동해야만 핵심 설명을 읽을 수 있는 구조는 없앤다. 상세 규칙은 과정 옆에 작은 설명 또는 펼침 항목으로 둔다.

### 세 개의 중심 장면

1. **같은 내용, 다른 공간**: 균일한 3열 사진 피드가 실제 8칸 플래터로 이동한다. 같은 위젯의 크기와 위치가 달라지는 것을 보여 주고 직접 재배치할 수 있게 한다. 위젯 모음에는 모양·이름·설명·크기를 함께 표시한다.
2. **원본의 출처가 끝까지 이어지는 디토**: 소라의 원본→지우의 사본→그룹에 공유된 원본 카드→하은의 사본을 하나의 장면에서 읽을 수 있게 한다. 원작자 칩과 전달 경로는 유지하되, 사본을 다시 디토할 수 있다는 인상을 주지 않는다.
3. **신호가 맞고 친구가 되는 순간**: 떨어진 ASCII 신호 두 개가 단계 색과 위상을 맞춘 뒤 심볼로 모인다. 주파수 충족은 신청이 열리는 상태이며, 친구가 되는 마지막 변화에는 상대 수락이 필요함을 구분한다. 강한 스크롤 장면은 여기에 집중한다.

### 이미지가 없는 상태의 디자인

- 사진·영상·앱 캡처용 영역은 비율, 배경, 프레임, 텍스트와의 관계를 완성한다. 외부 사진이나 더미 장면으로 채우지 않는다.
- 실제 위젯 UI와 브랜드 심볼은 코드로 구현된 콘텐츠이므로 그대로 보여 준다. 위젯 안에 사진이 필요한 경우에도 예시 사진 대신 의도적으로 비운 미디어 필드를 쓴다.
- 이미지 교체 규격은 별도 문서에 적고, 공개 화면에 파일명·픽셀 규격 등 제작자용 정보를 반복 노출하지 않는다.

### 그대로 복사하지 않을 부분

- 참고 사이트의 긴 페이지 수와 수많은 sticky 구간을 합치지 않는다. 사용자 스크롤을 잠그거나 강제로 이동시키는 로직은 도입하지 않는다.
- Skeep의 서체·색·브랜드 그래픽은 옮기지 않는다. Ditto의 디자인 시스템이 우선이다.
- 모션 줄이기 설정에서는 완성된 상태와 수동 단계 전환을 제공한다. 터치·키보드로도 같은 내용을 확인할 수 있어야 한다.
