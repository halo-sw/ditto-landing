## 세 장면의 정확한 상태

### 플래터

앱 격자 엔진으로 옮기기·밀어내기·같은 크기 교환·크기 변경을 처리한다. 일반 피드와 플래터는 같은 위젯의 위치·크기가 이동하는 장면으로 비교한다. 세 미니맵은 실제 배치 좌표를 축소한 것으로 선택한 배치가 그대로 적용된다. 키보드는 방향키로 이동, Shift+방향키로 크기를 바꾼다.

14종: 소셜, To-do, 방명록, D-Day, 스티커 보드, 포스트, GIF, 상태, 플레이리스트, 텍스트, Together, 이미지, 음악, 영상. 미디어 내용은 빈 필드로 두고 CD·메모·목록·출처 칩 등 실제 형태를 보여 준다.

### 디토

1. 소라가 원본을 디토 허용. 허용 가능한 위젯 3개 한도.
2. 지우가 대상·원작자를 확인하고 3초 누름. 포인터/키보드 모두 지원하며 중간에 놓으면 취소.
3. 내용과 원작자 출처가 함께 지우 플래터의 맨 앞에 삽입. 원작자 알림과 1/3칸 표시.
4. 지우가 그룹에 공유한 **소라 원본 카드**를 하은이 발견. 공유자 지우와 원작자 소라를 구분한다. 사본을 다시 디토하는 장면이 아니다.
5. 하은이 같은 원본을 디토. 소라의 출처는 남지만 프로필/플래터는 아직 잠겨 있고 점 매트릭스 파형과 주파수 안내가 나온다.

이미지/GIF/영상으로 설명한다. 음악은 디토 대상이 아니다. 소스 상세는 컴포넌트 명세 참조.

### 주파수

최근 교류의 예시를 네 단계(잔잔→선명→곧 열림→열림)로 보여 준다. 두 ASCII 신호는 간격·주기·위상이 맞아 가면서 실제 디토 로고 경로의 글자 마스크로 모인다. 마지막 색은 **신청 가능**이다. 애칭/편지를 넣어 신청하고 상대 수락을 눌러야 **친구** 상태로 바뀐다.

21일은 교류 관찰 창을 설명하는 한 예시이며 자동 친구 타이머가 아니다. 실제 점수·달성률을 표시하지 않는다. 체험 신청은 서버에 전송하지 않는다. reduced-motion에서도 단계 버튼과 신청/수락은 동작한다.

## 이미지 필드 계약

임시 사진·스톡 사진·더미 앱 캡처를 표시하지 않는다. 흰 여백과 중성 표면 안에 실제 콘텐츠가 차지할 크기·비율을 고정했다.

|---|---|---|---|
| 주파수 앱 화면 | `[data-media-slot="app-frequency"]` | 390:844 | 전체 화면 유지, `object-fit:contain` |
| 친구 피드 | `[data-media-slot="app-feed"]` | 390:844 | 전체 화면 유지 |
| 그룹 채팅 | `[data-media-slot="app-groupchat"]` | 390:844 | 전체 화면 유지 |
| 카메라 | `[data-media-slot="app-camera"]` | 390:844 | 전체 화면 유지 |
| 포토부스·캠코더·무전기·편지 | `.v9-analog-slot`의 `data-media-slot` | 1:1 | 오브제/장면을 잘라내지 않고 배치 |
| 위젯 사진·GIF·영상 | `.v9-field` | 선택한 위젯 칸 비율 | 앱 위젯 영역에 맞춰 넣음, 외곽·배지·출처는 유지 |
| 초대장 사진 | `#h8CamC`→`#tkPh` | 촬영 3:4 / 카드 왼쪽 면 | 사용자 사진만 사용, 브라우저에서 크롭 |

실제 에셋을 전달받으면 해당 필드 내부만 교체한다. 위젯 미디어를 넣을 때는 `prepare.js`의 미디어 제거 정책에서 해당 승인된 위젯을 허용하고 나머지 내용은 그대로 둔다. 종류·크기·배치 데이터는 교체하지 않는다.

## 초대장과 실제 서버

사진 찍기 또는 로컬 파일 선택 → 5가지 색감 → 이 사진으로 초대장 만들기 → 이름/아이디 → 사진 카드 저장은 브라우저에서 완료한다. PNG 1200×760에 실제 촬영 사진·이름·아이디가 들어간다. 발급 전에는 번호와 코드를 미발급으로 표시한다.

실제 코드는 기존 `claim_launch_ticket` 응답만 쓴다. 이메일과 동의를 거쳐 발급된 번호/코드를 저장한다. 이름/아이디만으로 유효 코드를 꾸며 내지 않는다. 이메일 수집 단계를 없애려면 서버 계약 변경이 별도로 필요하다. 사진 자체는 서버로 보내지 않는다.

공개 앱과 TestFlight 기능 범위의 차이를 카메라 안내에 적었다. 미리보기에서도 기존 좌석표/스티커/코드 발급은 실제 서버와 연결되므로, 검증에서는 모든 외부 요청을 차단하고 발급 응답을 모의 처리했다.
